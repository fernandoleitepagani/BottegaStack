# Worktree cleanup

1. Snapshot and audit. Record `df -h /`, then run `<maestro dir>/scripts/bottega worktree audit [-b <pr-base-ref>] [repo-path]` (wraps `worktree-audit.sh`, Mechanize It). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.claude/worktrees/x` (Mechanize It). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it (from `~/.claude/projects/<slug>/`), then suggests a bucket. The transcript scan is slow, so background it. Claude Code worktrees under `.claude/worktrees/` show up in `git worktree list` like any other.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (Prove It Works). Get that set from the user and cross-check every candidate. The audit has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (Guard the Context Window, transcripts are bulk). Use `subagent_type: "Explore"` and tell it not to edit files. A pinned chat spawns candidate and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar.
4. Pause on irreversible loss (maestro **Autonomy**). `wip:N` is N tracked uncommitted edits, `scratch:N` is N untracked files, `bottega-state` is run state under `.bottega/` (ledgers, handoffs, trails), and `unknown` means git could not read the worktree. All of them are lost on removal and none is in the branch, so show what is there and get a decision first. Only `clean`, merged, and not in use proceeds without asking.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts only (after step 4 cleared run state and untracked files), `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Other reclaimers. Package caches are usually the next-biggest win (pnpm, npm, uv, cargo, yarn, and brew on macOS). On macOS only (check `uname`), also look at Xcode `DerivedData`. Clear only caches the user has not said to keep.

This is the one workflow that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
