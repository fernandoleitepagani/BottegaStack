# Laziness protocol
The best change is the smallest one that fully works. Less is the default; add only what survives subtraction.

- Check whether the repo already has the function, skill or pattern; reuse or extend it before writing new.
- Write only what the goal needs; no speculative options or fallbacks.
- Delete dead code, duplicate rules and unused options first; prefer deleting or reusing over adding.
- No unrelated fixes in the same change.
- For a refactor, put tests before and after and keep behaviour the same.
- Use expand-contract when a change cannot land in one step.
