# Changelog

## Unreleased
- New: `maestro playwright doctor` reports `node:`, `playwright:` (the installed version beside the pin, `PW_PIN` 1.65.0 in `bin/maestro`), and `chromium: yes|no` in the cache dir `~/.cache/bottega/playwright`, exiting 0 only when all three hold and printing a `missing:` line otherwise; `maestro playwright install [--yes]` installs that pinned Playwright and Chromium into the cache dir only (never the repo), asks on a terminal, refuses in a non-interactive shell without `--yes` and downloads nothing, and does nothing when `doctor` already exits 0. A UI project (a root `index.html`, or a `package.json` with a UI framework or a `dev` script) whose newest run's SPEC names UI files gets a `playwright not installed` mention in the SessionStart tools hint and in `maestro doctor`, silenced by `BOTTEGA_NO_TOOL_HINT=1`; backend-only work stays silent. Master Step 2 offers the install with `AskUserQuestion` before the first builder wave, on every run until `doctor` exits 0.
- New: `maestro shot <url|file> [--viewport WxH] [--dark] [--text] [--out <name>]` renders one page in headless Chromium through `resources/playwright-shot.js`, the only Playwright call in the stack, and writes `<name>.png` (plus `<name>.txt` with `--text`) to the newest run's `shots/` dir, else `<state>/shots/`, never the repo; it defaults to a 1280x800 viewport, prints each artifact path, exits 1 with `maestro shot: playwright is not installed; run maestro playwright install` when Playwright is missing, and exits 2 on bad flags, a bad viewport, or a missing file. The `verification` and `create-verification-skill` skills and the ten design skills (`animation`, the seven `better-*`, `frontend-design`, `web-design-guidelines`) point to it for mobile and desktop, light and dark captures; the design skills stay standalone with a conditional line, and master Step 4 has the reviewer capture before/after evidence with it.
- Changes: `maestro build <run> <task>` (`--block`, `--wait`, and `--revise`) now runs `maestro check` in the task worktree and then `maestro verify-task` after every build report, including a `STATUS: DONE` report with no commits and a `BLOCKED` or `FAILED` one. It prints `verify-task: PASS` and exits 0, or prints each `FAIL <rule>: <detail>` plus `verify-task: FAIL; task stays BLOCKED (...)` and exits 1, so BLOCKED builds now exit 1; a HEAD-bound waiver prints `verify-task: WAIVED (<reason>)` and exits 0 for a DONE report, while a non-DONE report never passes. Master Step 2 replaces the prose acceptance check with the command and asks for the user's yes before a waiver, Step 3 notes the build already recorded the check, and WORKFLOW, SETUP, and the playbooks say the same.
- New: `maestro verify-task <run> <task> [--waive "<reason>"]` applies the five task acceptance rules to the task worktree: the builder report is `STATUS: DONE`, the worktree has commits on the run branch, the test commit came first (skipped for `Test first: none` or `n/a`, and a test file named in that field counts), every changed file is in the task's backticked `Allowed files`, and `maestro check` passed for the worktree HEAD. It prints one `FAIL <rule>: <detail>` line per broken rule and exits 1, prints `verify-task: PASS` and exits 0 when all hold, and honors a waiver recorded for the current worktree HEAD (`verify-task: WAIVED (<reason>)`, exit 0); a bad run or task id exits 2 before any state is written. The planning skill now asks for backticked `Allowed files` and a `Test first:` naming the test file.
- Fixes: `maestro build --review <run> <task>` and `build --review --here <slug>` check before they review: they reuse a fresh PASS record for the checkout HEAD when the tracked tree is clean, or run `maestro check` there, start the `review-code` reviewer only on PASS, and otherwise print the check output and exit 1 without starting the reviewer; the worktree path and the check gate are shared helpers (`task_worktree`, `ensure_check`), and master Step 4, WORKFLOW Step 4, and the playbooks no longer order the gate before the review.
- New: `maestro spec` validates the AC lines before it saves (`spec_ac_rows`, one awk pass): one AC per line, `Proof:` on the same line, a reason for `Proof: none`, and unique ids; the last `Proof:` on the line decides, so AC prose that quotes `Proof: none` does not opt the criterion out; a bad line exits 1 with `maestro spec: line <n>: <reason>: <line>` and leaves spec.md and `tasks/` untouched, while a SPEC with no AC lines still saves. `maestro gate <run> --proof` fails a full run whose SPEC has no acceptance criteria with `GATE: FAIL (proof: SPEC has no acceptance criteria)` and lists each `Proof: none` criterion as `proof none: AC<n>: <reason>` before its verdict; the planning skill and WORKFLOW show the AC format.
- Fixes: `maestro spec` refuses a source that is its own destination (the direct path or a symlink to it) with `maestro spec: refusing to read the spec from its own destination: <file>` and an empty source (a 0-byte file or empty stdin) with `maestro spec: empty spec: <file|stdin>`, saving through a temp file (created under umask 077 and removed by a trap on every exit path) and atomic rename with no temp left behind, so a spec can no longer be truncated before it is read; `maestro build <run> <task>` exits 3 and `maestro gate <run>` fails with `spec.md is empty, re-run maestro spec` when spec.md is 0 bytes. Likely cause: self-truncating redirect; issue stays open (issue #39).
- Fixes: `maestro check <run>` records `checks/<sha>.result` and `checks/<sha>.log` for the checked HEAD and refreshes `checks.result` as the latest record; `maestro gate <run>` reads only the record for the current HEAD, so checks and review can run per task worktree in parallel and a check in another worktree no longer makes the gate stale, while a new commit still reports `GATE: FAIL (checks stale: <sha> != <head>)` and a run with no record still reports `GATE: FAIL (no checks.result)`.
- Fixes: `session-handoff` writes the handoff to `${BOTTEGA_HANDOFF_DIR:-/tmp}/<repo>-handoff-<slug>.md` (mode 600, disposable) instead of keeping it only in chat, replies with `HANDOFF: <path>` and a `NEXT:` line, and the master prompt names the same file as its one allowed write outside the repo; the docs, playbooks, and README say so too, and `scripts/lint.sh` fails when the skill and `agents/master.md` disagree on the path.

- Fixes: two `maestro build --here` callers sharing one build now both exit 0 and each prints `task: <slug>` plus a `report: <path>` whose file exists, with exactly one caller collecting the rc; `build_collect` claims the result with an atomic rename (`mv` to `$rcfile.collecting.$$`) so a second caller reports `already collected by another caller` instead of reading a removed rc, and the run marker is removed only after the report is written, so the waiter no longer races ahead of it (issue #34).
- Fixes: every run-taking command (`spec`, `check`, `gate`, `verify`, `log`, `hold`, `resume`, `build` including `--here`, `--review`, and `--status`, `watch`, `worktree create|prune`, and `report --close|--finding`) shares one run-id validator and rejects an empty, leading-hyphen, or traversal-style id with `maestro <cmd>: bad run id: <id>` on stderr, exit 2, before it resolves or writes any state; `resolve_run_dir` and `run_state_dir` return 3 for a bad id so callers can tell it from "not a git repository" (issue #37).

- New: `maestro statusline install [--yes]` points Claude Code's status line at `maestro watch --line`; it prints the JSON it will merge, asks before applying, backs up `settings.json` to `settings.json.bak.<epoch>`, keeps other keys, writes a mode-700 `<config>/statusline.sh` with a `# bottega-managed statusline` marker and an absolute maestro path, and never replaces a custom `statusLine.command` or an unmanaged script; `maestro statusline status` reports `statusLine`, `refreshInterval`, and the command class read-only, and the SessionStart `tools hint` adds `Status line not set up. Run: maestro statusline install` when the settings are missing or the status line is incomplete (silenced by `BOTTEGA_NO_TOOL_HINT=1`).

## 0.7.0 — 2026-11-12

- New: `maestro skills install <name>... | --all` copies standalone skills from `skills/standalone.txt` into `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/` so they run as plain slash commands; `maestro skills list` shows each one's status, `maestro skills uninstall <name>... | --all` removes only managed copies, every copy carries a `.bottega-managed` marker so `install` refreshes it and refuses an unmanaged target, installing a skill also pulls in the standalone skills it Loads, copies do not update with the plugin (re-run `install`), and a lint-checked list regenerated by `./scripts/standalone-skills.sh --write` decides which skills are standalone; installed copies keep the source directory's mode, and every skills command fails before writing when neither `CLAUDE_CONFIG_DIR` nor `HOME` is set; run-id and skill-name validators spell out the ASCII class, so an uppercase name is rejected under any locale (bash 3.2 on macOS matched a `[a-z]` range against uppercase); the docs note that some standalone skills mention the master, planner, or `maestro` commands that only apply with the plugin enabled (issue #27).
- Fixes: the repo's own project memory moved to `.claude/CLAUDE.md`, which imports `@../AGENTS.md`, so Claude Code loads it for contributors and `claude plugin validate` no longer warns that a plugin-root `CLAUDE.md` is not project context; `scripts/lint.sh` rejects a root `CLAUDE.md` and requires that import (issue #26).
- Fixes: the plugin ships a 512x512 PNG icon at `.claude-plugin/icon.png`, so `claude plugin validate` no longer warns `ICON_MISSING`; `scripts/lint.sh` fails unless that icon exists, starts with the PNG signature, and has a 512x512 IHDR (issue #25).
- New: `maestro --version` (also `-V` and `maestro version`) prints `maestro <version>` from `.claude-plugin/plugin.json` (`unknown` when the file or field is missing) before command dispatch, and `maestro doctor` prints a `version: <version>` line (issue #24).
- Fixes: `/maestro` no longer pins the master to Opus, so it runs on the session model; `scripts/lint.sh` rejects a `model:` in any `commands/*.md` frontmatter, and the docs explain choosing the master model with `claude --agent bottega:master --model <model>` and per-role routing with `/maestro-models` (issue #19).
- Fixes: new `maestro hold <run> "<reason>"` records an escalation (a `hold` file with the reason and a timestamp) in the run's state directory, including light-path slugs under `quick/<slug>`, and `maestro hold --clear <run>` removes it; both reject a run id outside `[a-z0-9-]`; `maestro guard stop` lets the session end with `run <slug> is on hold: <reason>` when every open run is on hold, `maestro build --status` prints `HOLD: <reason>`, and the master runs it instead of completing todos when it escalates or a builder is `BLOCKED`; new `maestro resume <run>` clears a `paused` marker and any hold so a resumed run is tracked again, and a merged, pr, or rejected close removes the directory (issue #23).
- Fixes: `maestro report --close <run> --outcome paused` writes the trust-log line but keeps the run's state directory (spec, tasks, build records, check results) and adds a dated `paused` marker so a resume can use it; `maestro guard stop` treats a paused run as closed, while `maestro spec`, `maestro build --status`, and `maestro verify list` still resolve it, and a later close with `merged`, `pr`, or `rejected` removes the directory as before (issue #21).
- Fixes: when two `maestro build` callers attach to one build, the one that does not collect the result stops as soon as the run marker disappears and prints `task: <slug>`, `already collected by another caller`, and the report path, instead of sleeping the full `BOTTEGA_BUILD_WAIT` for a file another caller removed (issue #18).
- Fixes: `maestro start` ignores untracked files (for example `__pycache__/` left by `scripts/check`) in its clean-tree check, so a repo whose only changes are untracked can start a run; modified or staged tracked files still refuse with `working tree is dirty; commit or stash first`, and `maestro gate` keeps its strict check (issue #22).
- Fixes: `maestro gate <run>` names an unknown run on stderr as `maestro gate: no such run: <run>` and exits 1, the same wording as `maestro check`, instead of reporting `GATE: FAIL (no checks.result)`; a known run with no check result still reports that failure (issue #17).
- Fixes: `maestro start` validates the git repo, branch rule, and clean tree before it auto-inits, so a refused start (for example on `main` without `--branch`) exits 1 and leaves the repo byte-for-byte unchanged: no `AGENTS.md`, `CLAUDE.md`, `.claude/`, or `scripts/` (issue #16).
- Fixes: `maestro build --review --here <slug>` with no light-path state fails before any model call with `maestro build --review: no such run: <slug>` and exit 1; `maestro build --review <run> <task>` fails the same way for an unknown run (issue #15).
- Fixes: when more than one `maestro` is on `PATH` (a plugin update can leave an older copy first), `maestro doctor` and the SessionStart `maestro tools hint` warn in PATH order, name every distinct copy with its plugin version, and mark the first as winning; a symlinked copy and its target count once and report the target's version, empty PATH entries are skipped, one copy prints nothing new, and `BOTTEGA_NO_TOOL_HINT=1` still silences the hint (issue #20).

## 0.6.0 — 2026-11-10

- CI fixes: bash 3.2 (macOS) compatibility (no `$(case)`, no associative arrays, safe empty-array expansion under `set -u`), restored `has_dependency_manifest` for `doctor`, e2e pins `XDG_CONFIG_HOME`.

- New user-invoked `teach` skill: teaches a topic or part of the codebase one idea at a time, with checks and small exercises.

- `maestro tools install [--yes]` installs missing rtk and gitleaks after asking; a SessionStart hook prints a one-line hint when they are missing (`BOTTEGA_NO_TOOL_HINT=1` silences it).

- New `design` skill category: `frontend-design` (Anthropic), `better-ui` and its siblings plus `interface-review` (jakubkrehel/skills), `agentation`, an original `animation` skill, and `web-design-guidelines` moved in. The builder uses `frontend-design`, `animation`, and `better-ui` for UI work.

- `/maestro` is a thin command that loads `agents/master.md` at run time; removed `scripts/gen-command.sh` and the generated copy.
- `maestro doctor` prints whether the optional `rtk` is installed; `docs/SETUP.md` gains a Token savings section (install, license, caveats).
- `orchestrate` (from pstack, rewritten, user-invoked only): coordinate a program of PR-sized units with a `PLAN.md` ledger, one owner and one reviewer-verifier per unit, `maestro gate --proof` per unit, live supervision, at most 3 builds in flight, and the user merging every PR. `maestro worktree create <run> <task> --branch <name> [--base <ref>]` creates a worktree on a user-named branch that `prune` never deletes.
- `autonomous-run` (from pstack, rewritten, user-invoked only): one task to a command-checkable exit condition, one verified change per iteration, reverted with `git revert` when it did not help, a `maestro log` row each time, an iteration and time cap, ends on a local branch.
- `architect` and `arena` (from pstack, rewritten, user-invoked only with `disable-model-invocation: true`): design twice before the SPEC, and compare 2 or 3 headless-builder candidates with a blind judge.
- From pstack (credited, rewritten): `show-me-your-work` (decision log via `maestro log`, kept in the temp state root), `ketchup`, `correct` (lint-first fixes for repeated findings; the retro and master Step 8 load it), the benchmark checklist inside `perf`, runtime and trace forensics inside `investigate`, and the comment pass inside `simplify`. `autopilot` logs a row per item.
- `eval` playbook (adapted from pstack): compare a variant of the stack or a skill against the installed one on the same task, with headless builders as candidates, a blind judge on the reviewer model, and a transcript check. `BOTTEGA_PLUGIN_DIR` makes the headless runner load a checkout of the stack with `--plugin-dir`.
- Proof gate: SPEC criteria are `AC<n>` with a `Proof:` line; `maestro verify record|waive|list` keeps rows in the run's state dir (PASS needs an evidence file and a reviewer, second-opinion, or master, never the builder; INCONCLUSIVE and stale rows fail) and `maestro gate <run> --proof` blocks approval until each criterion has a PASS for the current HEAD or a user-approved waiver. `create-verification-skill` now follows pstack's shape (Launch, Doctor, Drive, Evidence, Cleanup, per-feature map); new `maintain-verification-skill`.
- Trust log: `maestro report --close` appends one line (date, run, playbook, risk, fix rounds, checks, outcome) to `trust.log` in the temp state root; `maestro report --trust [n]` summarizes the last runs. Report only; nothing is switched on by it.
- Branches are yours: `maestro start` works on the branch you are on and only creates one with `--branch <name>`; task branches are `<branch>-<task>`, stay local and are never pushed; `worktree prune` deletes the merged ones (`git branch -d`, never forced) and keeps unmerged ones. The run branch and remotes are never touched.
- Principles trimmed from 21 to 15: `prove-it-works` absorbs `outcome-oriented-execution`, `laziness-protocol` absorbs `subtract-before-you-add`; `model-the-domain`, `escalate-after-two-fixes`, `stay-in-allowed-files`, and `no-secrets` are dropped (their rules live in `domain-modeling`, the master Step 5 text, the builder contract, and `untrusted-content`). `untrusted-content` gains the secrets rule.
- The 21 principles are now reference files inside the `principles` skill (`references/<slug>.md`) instead of 21 separate skills; citations keep the same slugs. Skills: 63 to 42.
- The quiz is shown in chat before the decision prompt and is never written to the PR body, a commit message, or a file.
- README banner and "what makes it different" section; `resources/verify.sh` temp names renamed to `bottega-verify`.
- New playbooks: `investigate`, `perf`, `prototype`, `ship`, `autopilot`, and `pause` (covers pause and resume); `closeout` gains a merge-readiness gate that blocks merge until unmet items are fixed or waived.
- Cheap first-pass review: for `low` risk the master runs the headless `maestro build --review` first; only findings escalate to the Claude reviewer.
- Effort routing: `~/.claude/rules/bottega-models.md` holds `role: value, effort` per role; the master passes both per Agent call and headless builds pass `--effort`.
- `maestro stack` detects the repo's language, package manager, commands, and frameworks; the master confirms it and records the profile in `AGENTS.md`.
- `maestro doctor` warns on missing gitleaks, a tracked `.env`, no dependency-update config, and no CI security job.
- New skills: `interrogate` and `blast-radius` (report-only), plus `linux-sysadmin`, `podman-operator`, and `bash-scripting` in the new `sysadmin`, `containers`, and `devops` categories, adapted from ChrisTitusTech/titstack (MIT).
- Builds report `tokens: in <n> out <n>` and `steps: <n>`; the USD cap and every cost figure are gone, and the 30-minute timeout is the only stop.
- Cleanup: removed the dead `claude/global/` snippets, `VERSION` (the plugin manifest is the source), the unused ADR template, the legacy-migration code in `maestro upgrade`, the stale `doctor` upstream-skills check, the local-settings comparison in the lint, and duplicated run-state and project-file docs. Deleted all merged `pagani/*` branches and builder worktrees.
- Renamed the stack to Bottega: repository and docs `BottegaStack`, plugin `bottega`, CLI and slash command `maestro`, env vars `BOTTEGA_*`, config `~/.config/bottega`, branches `bottega/<slug>`. No compatibility aliases; the `prototype/` research folder is removed.
- Run state moved out of the repo to a per-repo state directory in the system temp dir (`PAGANI_STATE_DIR` overrides it), shared by worktrees. `pagani start` creates the branch `pagani/<slug>` and the state directory; `pagani spec|check|gate|report` replace `pagani job`, which prints the replacement and exits 2. Nothing is written into the repo or a worktree.

The Stop hook is driven by the todo list.
- Playbooks rewritten in pstack style: routing table, risk modifier, light path, the `loop` rule for external waits, and a `figure-it-out` fallback. Each playbook is a short numbered checklist copied into the todo list; every run ends with verbatim before/after evidence and claims labelled measured, inferred, or guessed.
- `principles` is now a short index; each of the 21 rules is its own `principle-<slug>` skill, so `principle <slug>` citations stay stable.
- `agents/master.md` shortened to about 130 lines, citing principles and skills instead of restating rules; `commands/pagani.md` regenerated.
- Shortened `review-code`, `implementation`, `interview`, `planning`, and `closeout` with the same report formats and decision options.
- New skills: `how` and `why` (read-only, evidence-based explanations), `figure-it-out` (one-off playbook), `create-verification-skill` (project `.claude/skills/verify-*`), and `automate-me` (personal mode skill from transcripts, after approval).

- `pr-babysit` playbook and a `loop`-based rule for waiting on external events instead of idling.
- CI (`.github/workflows/ci.yml`) runs the lint on Ubuntu and macOS, checks that the generated command is fresh, and validates the plugin manifests when `claude` is available.
